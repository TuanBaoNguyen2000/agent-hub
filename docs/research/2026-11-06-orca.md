# Đánh giá Orca (2026-11-06)

**Nguồn:** <https://github.com/stablyai/orca>, commit `95af9000` (2026-11-06), license MIT. Đã đọc README và một phần mã (`src/main/claude-accounts/`, `src/main/codex-accounts/`, `src/main/rate-limits/`, `src/main/agent-hooks/README.md`, `src/shared/ai-vault/`, `orca.yaml`). Chưa chạy thử.

**Kết luận:** Orca là IDE điều phối agent (terminal nhúng, worktree, chat UI riêng, browser, mobile, cloud), phạm vi lớn hơn và khác hướng AgentHub. Không theo mô hình tổng thể. Có ba ý tưởng đáng cân nhắc, xếp theo giá trị ở mục cuối.

## Orca làm gì

- **Workspace = worktree:** mỗi task một Git worktree, agent chạy trong terminal nhúng (PTY) hoặc chat UI riêng của Orca; `orca.yaml` khai báo script `setup` chạy khi tạo worktree.
- **Account:** nhiều account Claude, Codex, Cursor, Grok. Mỗi account một thư mục cấu hình riêng (Claude theo `CLAUDE_CONFIG_DIR`, Codex theo `CODEX_HOME` do Orca quản lý), đăng nhập bằng flow của CLI.
- **Dùng chung lịch sử phiên giữa account:** `claude-profile-history.ts` chuyển các thư mục `projects`, `file-history`, `todos`, `plans`, `transcripts`… của từng profile về home mặc định rồi thay bằng symlink (trừ `sessions`, là registry tiến trình của từng thư mục); có gộp prompt history và giữ lại mục xung đột. Codex có cài đặt `codexShareHistoryAcrossAccounts` (mặc định bật) để liên kết `sessions` giữa các home. Kết quả: `claude --resume <id>` hoặc `codex resume` chạy được ở account khác với account đã tạo phiên.
- **AI Vault:** quét transcript của khoảng 25 agent, tìm kiếm toàn văn, dựng lệnh resume đúng agent, cwd, home và shell.
- **Trạng thái agent:** cài hook vào cấu hình từng agent, hook POST về server loopback của Orca (trạng thái, prompt, tool, session id); dự phòng bằng OSC 7501 agent tự ghi vào luồng terminal. Dùng để báo "agent đang chờ duyệt / đang hỏi" qua thông báo hệ thống và app mobile.
- **Usage:** Claude đọc OAuth credential của account rồi gọi endpoint usage; Codex qua app-server.
- **Khác:** điều phối agent cha–con, review diff có ghi chú gửi lại agent, GitHub/Linear, automation theo lịch, skill bundle chia sẻ qua cloud, plugin.

## So với AgentHub

| | Orca | AgentHub |
|---|---|---|
| Vai trò | IDE thay thế, chạy agent bên trong | Launcher + context manager, mở app/CLI chính thức |
| Terminal | PTY nhúng | Terminal ngoài ([ADR-009](../decisions/009-external-terminal.md)) |
| Desktop app | Không mở Claude/Codex Desktop | Desktop và CLI ngang hàng |
| Account | Thư mục cấu hình riêng | Giống ([ADR-018](../decisions/018-account-login-and-identity.md)) |
| Chuyển account | Resume chính phiên đó (lịch sử dùng chung) | Tài liệu + handoff do agent viết ([ADR-019](../decisions/019-agent-maintained-context.md)) |
| Usage | Đọc OAuth token, gọi API | Lệnh của CLI chính thức (FR-018, không giữ token) |
| Cloud/mobile | Có | Local-first (NFR-001) |

Phần không hợp: terminal nhúng và chat UI riêng (trái TDD §1.4 và ADR-009), đọc OAuth credential để lấy usage (trái NFR-004), cloud, mobile và skill sharing qua server (trái NFR-001), điều phối nhiều agent song song (ngoài nhu cầu hiện tại).

## Ý tưởng có thể mượn

1. **Resume phiên CLI ở account khác (giá trị cao nhất).** Đây là cách chuyển account không mất hội thoại cho CLI, bổ sung cho handoff: khi hết quota ở account A, mở account B với `claude --resume <id>` trên cùng phiên. Cần spike trước: Claude Code có chấp nhận transcript tạo bởi account khác không, ảnh hưởng của symlink lên `CLAUDE_CONFIG_DIR` của account chính (phải hỏi trước, FR-017), cách Orca hoàn tác ("Undo legacy session sharing"), và Codex `sessions` tương tự. Có thể làm opt-in theo cặp account thay vì symlink cả thư mục. Không áp dụng cho Desktop.
2. **Danh sách phiên theo project kèm nút resume.** AgentHub đã đọc transcript cho fallback (TDD §7.6) và có lịch sử mở; có thể liệt kê phiên Claude/Codex của project (đọc `projects/<cwd-slug>/*.jsonl`, `sessions/**/rollout-*.jsonl`), hiện tiêu đề, thời gian, account, và mở lại bằng lệnh resume dựng như `buildAiVaultResumeCommand` (quote theo shell, đặt cwd và home). Hợp với FR-104 (search) và FR-105.
3. **Báo khi agent chờ người dùng.** Hook `Notification`/`Stop` của Claude và hook của Codex có thể gọi một lệnh nhỏ của AgentHub để hiện thông báo macOS hoặc đánh dấu trên trang project. Chạy được với terminal ngoài vì hook do CLI gọi. Phải là opt-in và cài cùng cơ chế cài skill/MCP theo account (FR-017); AgentHub có thể đang đóng nên cần đường dự phòng (ghi file trạng thái).

Ý tưởng nhỏ hơn, đã có chỗ trong roadmap:

- **Script setup khi tạo worktree** (`orca.yaml`) cho FR-102; với Unity có thể dùng để copy `Library/` hoặc cấu hình cục bộ.
- **Ghi chú trên dòng diff gửi lại agent** cho FR-101, dưới dạng copy một gói prompt (không cần chat UI).

## Task và tài liệu

Đọc thêm `src/renderer/src/components/task-page/`, `jira-prompt-templates.ts`, `components/editor/` (markdown, autosave), `src/main/text-generation/`, `src/cli/handlers/orchestration/task-handlers.ts`.

**Orca không có tài liệu context hay task cục bộ như AgentHub.** Task của Orca có hai loại:

- **Issue của tracker ngoài** (GitHub, GitLab, Linear, Jira): trang Task liệt kê, lọc, phân trang, có bảng cột của GitHub Projects; drawer chi tiết sửa tiêu đề, mô tả (editor Markdown), trạng thái, người nhận, comment, sub-issue; sửa lạc quan có hàng đợi và rollback. Từ một issue tạo workspace (worktree) gắn với issue đó (`linkedIssue`, `linkedLinearIssue`, `linkedPR`), thẻ workspace hiện trạng thái issue.
- **Task điều phối** do agent điều phối tạo qua CLI: `orca orchestration task-create --spec … --deps … --parent …`, trạng thái `pending/ready/dispatched/completed/failed/blocked`, giao cho worker, có "gate" để người dùng duyệt.

Tài liệu là editor chung: Monaco cho code; Markdown có chế độ rich (TipTap) và xem trước (`react-markdown` + `remark-gfm` + `rehype-sanitize`, mermaid, KaTeX); autosave có luồng xung đột khi file đổi trên đĩa; quick open; kéo file vào prompt agent. Tóm tắt issue và commit message được sinh bằng cách chạy agent CLI ngầm (`text-generation/`).

| Ý tưởng | Áp dụng cho AgentHub | Ghi chú |
|---|---|---|
| **Mẫu lời nhắc theo task** (Jira: "Start implementation", "Investigate bug", "Write test plan", "Draft PR summary", cộng mẫu tự viết với biến `$jira-issue`, `$other-prompt`) | Nên làm. "Mở agent với task này" (ADR-023 mục 5) cho chọn ý định: làm task, điều tra lỗi, viết acceptance criteria, viết test plan, checkpoint; mẫu tự viết lưu theo project; biến `$task` (đường dẫn + tiêu đề), `$note` | Vẫn là phiên tương tác (ADR-021 mục 7); chi phí thấp, chỉ thêm i18n và một menu |
| **Task ↔ branch/worktree** (workspace gắn issue, hiện trạng thái hai chiều) | Một phần. ADR-023 đã có thuộc tính Branch; có thể hiện branch đó có tồn tại, đang checkout, dirty (ADR-017), và ngược lại hiện task trên lịch sử mở (`task_ref` đã có). Tạo worktree từ task để sau, cùng FR-102 | |
| **Phụ thuộc giữa task** (`--deps`, `--parent`, trạng thái `ready` khi phụ thuộc xong) | Có thể, chưa gấp. Dòng `Depends on: TASK-012` dưới `Status:`; màn Task hiện "chờ TASK-012" và chỉ ra task làm được ngay | Cần ADR, sửa khuôn §7.2 và ba skill |
| **Gate người dùng duyệt** | Đã có tương đương: chuyển Xong ghi "Verified by user in AgentHub" (ADR-021 mục 5) | |
| **Renderer Markdown** (`react-markdown` + `remark-gfm` + `rehype-sanitize`, mermaid) | Cân nhắc khi renderer tự viết (`Markdown.tsx`, 186 dòng) gặp giới hạn: list lồng nhau, sơ đồ mermaid agent hay viết, footnote. Không render HTML thô vẫn giữ được với `rehype-sanitize` hoặc bỏ `rehype-raw` | Thêm dependency, phải qua ADR-016 |
| **Xung đột khi file đổi trên đĩa** | Đã có (ADR-021 mục 9). Có thể thêm: xem diff giữa bản đang sửa và bản trên đĩa thay vì chỉ cho copy | Ý nhỏ |
| **Editor rich (TipTap)** | Không. Sửa theo mục + Markdown cả file (ADR-021 mục 3) đủ và giữ file sạch cho agent; TipTap dễ viết lại định dạng | |
| **Đồng bộ với GitHub/Jira/Linear** | Không, trong MVP. Task nằm trong file (ADR-019, ADR-023). Nếu cần sau: nhập một issue thành file task một chiều (link URL trong task), không đồng bộ trạng thái | P2 |
| **Sinh tóm tắt, commit message bằng agent chạy ngầm** | Không. Trái ADR-021 mục 7 | |

Code không đáng chép nguyên: kiến trúc gắn với PTY, daemon và cloud của Orca, xử lý WSL/SSH dày đặc. Phần đáng mượn là thiết kế và danh sách thư mục cần chia sẻ trong `CLAUDE_PROFILE_HISTORY_DIRS`.
